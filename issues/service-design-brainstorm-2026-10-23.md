# Designing a smooth local-AI service for the MSI Claw 8 AI+ — brainstorm results (2026-10-23)

## 1. TL;DR

- **Service shape:** one frozen, containerized vLLM lane (Gemma 4 26B INT4, ~16 GiB + 1.5 GiB KV) behind **llama-swap on 127.0.0.1:8080** as the only URL harnesses see; a host that **never suspends on AC**, reboots once a night when idle (the only documented reset for the Level Zero shared-memory leak), orders wg0 after network-online, and runs the stock Fedora `watchdog` daemon with the existing iwlwifi reload as its repair binary. Every unit proves itself (preflight → health → 1-token completion) before the gateway depends on it. Alerting is positive and partly off-box (07:15 "ready" line plus a dead-man check on a Spark). Resident budget: ~19 GiB, ~2 GiB under the 21 GiB ceiling (table in §3).
- **Top idea #1 — S39 Never-sleep-on-AC + guarded 04:35 reboot** (consensus 7.0): two config lines and one timer remove the P6 trigger and blunt P3; skeptic rated the full idea low, two of three judges rated the 15-minute core first overall.
- **Top idea #2 — T11 Bot memory as a git repo + restic to a Spark + monthly restore drill** (6.5): protects the only irreplaceable bytes; no skeptic verdict (gap-fill round).
- **Top idea #3 — S04 Quadlet template + vLLM `--config` YAML + llama-swap, ttl=0** (6.3): the already-decided container made operable; adopt two existing products, write no generator.
- **Top idea #4 — S38 Hardware watchdog + network self-heal ladder** (6.3): `/dev/watchdog` existence is unverified on Lunar Lake and the iwlmvm modprobe in the existing resume unit is probably a silent no-op on iwlmld kernels; the fix is smaller and more urgent than the idea's framing.
- **Top idea #5 — S41 LLM-free sentinel/ops bot** (6.3): `OnFailure=telegram-notify@%n`, a 07:15 ready-check, a tiny button bot, a Gatus/healthchecks dead-man on a Spark; never failure-only.
- **Workflow change #1:** `make` as the single entry point (env/image/serve/gate/promote) over the decided two-lane container, with three pre-commit lints (shellcheck, no-setvars, no-silent-patch-apply) that flag live defects today in `lunar_lake_serve.sh`, the installers and `Dockerfile.lunar-lake`.
- **Workflow change #2:** capture the ~4 live v0.32 patches as git-format files with `Upstream-Status` headers (they exist only in the venv today), run the 10-minute `getMemoryInfo` probe to delete the UMA patch, and add a weekly `git apply --check` against the newest vLLM tag that pings Telegram on change.
- **Workflow change #3:** turn the decided 5-gate suite into a runnable smoke/nightly split with a thresholds YAML and JSONL results (bench serve with the JIT request excluded, quant_kld against a committed `ref.json` captured on a Spark, 3-prompt greedy parity, MemAvailable ≥ 2.5 GiB, a curl|jq per-harness `cached_tokens` probe), wrapped in `run-gates.sh` with a timeout and an unconditional stable restore. Everything else (quantization, BF16 references, patch dry-runs, image builds, the Telegram gateway if you choose the S33 reversal) moves off the console.
- **Rule for when NOT to upgrade:** SKIP unless a tracked watchlist item closed or a CVE landed; at most one stable promotion per ~6 weeks; never in a busy week; never unattended on the console.

## 2. Method

The run used a diverge/converge pipeline: 16 ideators, one brainstorming technique each (SCAMPER, Six Thinking Hats, reverse brainstorming, first principles from the hardware, analogical transfer, jobs-to-be-done, morphological analysis, TRIZ, starbursting, worst-possible-idea, steal-from-the-pros, future-backwards/pre-mortem, lean value-stream mapping, constraint relaxation, Crazy 8s, biomimicry), generated 306 raw idea cards, and four gap-fill ideators added 47 more (353 in total) across memory/model policy, service architecture, reliability, NPU/multimodal, handheld form factor, user experience, Spark routing and dev workflow, which were deduplicated into **54 canonical ideas (S01–S54)**; a **gap report** then identified four uncovered layers (security/trust boundary, storage and model lifecycle, the NPU platform layer, "the handheld is still a handheld") and a second round produced **18 gap-fill ideas (T01–T18)**, for **72 canonical ideas**. Two **skeptic agents** reviewed each S-idea through separate lenses, feasibility (verdict `feasible` / `feasible_with_changes` / `infeasible`, blockers, required changes, memory and effort re-estimates) and value (`high`/`medium`/`low`/`none`, jobs served, pains relieved, prior art); their evidence lists cite the brief, the `issues/*.md` and `docs/*.md` files, local source checkouts, and web lookups, which are marked `[web]` in the verdicts (several lookups failed because docs.vllm.ai, docs.openvino.ai, tailscale.com and docs.openclaw.ai were outside the session's allowed network, and those claims are flagged as unverified). **Two ideas were rejected** (S19, S20; both "infeasible"/"none" or "feasible_with_changes"/"none"), **70 survived**. **Eight of the gap-fill ideas (T11–T18) received no skeptic verdict** and were scored by the judges directly. Three **judge agents** with declared angles (MVP-first, Reliability-first, Delight-first) then scored every surviving idea 0–10 and assigned a horizon; the consensus score below is the mean of the available judge scores (two ideas were scored by only two judges). All scores in this report are judge scores; all feasibility and value verdicts are skeptic verdicts; nothing here is a new measurement, and figures labelled *est.* are estimates from the verdicts, not data from the console.

**Where each component runs.** iGPU: exactly one vLLM engine (Gemma 4 by default; Qwen3-Coder only when a request names it). CPU: llama-swap, the gateway, preflight/FDR scripts, the sentinel bot, watchdog, tailscaled, mosh/tmux, and the GGUF fallback when vLLM is down. NPU: nothing until a mic test, `/dev/accel0` driver test and WhisperPipeline('NPU') smoke test pass (see §8). Sparks: the dead-man check, backups, the quant foundry and BF16 references, the weekly patch radar, optionally the Telegram gateway itself (S33 reversal variant), and the 122B fallback model the bots already route to.

### Boot and recovery sequence

1. Host boots into the default target; `wg-quick@wg0` is ordered `After=network-online.target` with its PostUp route exception made interface-agnostic (the documented boot race in `OPENCLAW_SETUP.md` is otherwise reproduced on every unattended reboot); `tailscaled` follows.
2. `llama-swap` starts and preloads the default profile: `vllm@stable` runs `ExecCondition=xpu-preflight` (`sync; echo 3 > drop_caches`, then `/proc/meminfo` arithmetic replicating the driver's usable-memory formula — no torch import; refuses with exit 75 if free < weights + KV + ~2 GiB, or if Shmem/MemAvailable has drifted from the post-boot baseline). A refusal is a condition skip, not a failure, so a `claw-retry.timer` (2–5 min, bounded counter) re-tries once memory recovers instead of looping.
3. `vllm-ready.service` polls `/health`, issues one `max_tokens=1` completion, and checks the startup log against `logcheck.yaml` (`Using FLASH_ATTN backend`, `cudagraph_mode NONE`, no "falling back to PyTorch reference attention", `--no-enable-prefix-caching` present on any GDN+MTP profile). The gateway unit `Requires=` it.
4. OpenClaw (later nanobot) starts; a oneshot sends one real-prefix request per harness to warm the prefix cache (OpenClaw's heartbeat keeps it warm afterwards).
5. The 07:15 ready-check posts a positive line ("Claw ready: gemma-4 resident, probe 0.4 s, 2 bots polling") and the Spark's dead-man receives a heartbeat.
6. Nightly at 04:35, if on AC, idle (`vllm:num_requests_running == 0`), no remote SSH session, and either a leak flag is set or the day count says so: graceful stop, `systemctl reboot`. This is the honest backstop for the Level Zero leak ("reboot only reliable reset", `vllm-v19-lunar-lake-findings.md` Finding 3).

### Failure modes and the mechanism that handles each

| Failure | Detection | Handling |
|---|---|---|
| vLLM crash (EngineDeadError, DEVICE_LOST, OOM) | unit exit; `ExecStopPost` scoped to `$INVOCATION_ID` | FDR bundle (journal, dmesg xe/iwlwifi/oom, meminfo) → preflight on relaunch; if free XPU stays < ~15 GiB after drop_caches, set leak flag, do **not** relaunch, let the reboot timer take it; bots fall to Spark/Anthropic via OpenClaw's existing connection-error fallback; one Telegram line |
| Live-but-dead server (`/health` 200, no tokens) | `claw-live.timer`: 1-token probe every 5 min only when idle; three strikes | graceful SIGTERM restart through preflight (never SIGKILL; both leak per Finding 3) |
| Restart loop burning the L0 pool | `Restart=no` + launch counter since boot | second failure → leak flag → reboot path, never a third launch |
| WiFi dead after sleep / wg0 before WiFi | watchdog probes (LAN gateway, `tailscale ping spark1`, Telegram `getMe`) | ladder: radio off/on → reload whatever op-mode holds iwlwifi (iwlmld on this kernel, not iwlmvm) → wg0 down/up → tailscaled restart; escalate past rung 1 only when WiFi is associated and the LAN gateway answers but the local stacks are dead (an AP/ISP outage must never reboot) |
| Suspend while serving | removed as a trigger: never suspend on AC; the facade/bot holds a short inhibitor while a request is running | battery suspend is allowed only in the handheld nice-to-have; treat as a planned stop |
| Kernel hang on resume | hardware watchdog **if** `/dev/watchdog0` exists (unverified on Lunar Lake; iTCO has no LNL entry, WDAT maybe) | `RuntimeWatchdogSec=120` only after the existence check; otherwise accept that a wake hang is a physical power-button event and avoid sleep on AC |
| Bad image after an upgrade | `vllm-ready` fails `logcheck.yaml` or the greedy canary | `podman auto-update` rollback to the previous digest (`AutoUpdate=local`); `:stable-prev` kept |
| Silence (box dead, WiFi dead, alert path dead) | dead-man switch on spark1 misses the heartbeat | Spark posts the alert; this is the only path that distinguishes WiFi-dead from all-green |
| Bot overwrites or loses MEMORY.md | nightly MEMORY.md diff line; hourly git commits | `git revert`; restic restore rehearsed monthly on a Spark |
| Gaming / Windows session (nice-to-have) | `game-watch` sees the Steam reaper; `claw windows` announces | stop vLLM with the leak check (or `/sleep?level=2` if the S07 probe passes), route bots to Spark, `grub2-reboot 'Windows Boot Manager'` so a power cycle always returns to Nobara |

Mechanism: an Arc Pro B60 24 GB in a TB4 enclosure as a second Level Zero device for the coder; the B580 (12 GB) is dead on arrival. Leverage: TB4 PCIe tunnel, xe multi-device. ### A rule for when NOT to upgrade

Adopt S45's reduced `UPGRADE_POLICY.md`, advisory not automatic: **SKIP** when no watchlist item (#40295/#41370, #53912, #43650/#48375, #54698, #54785, #54740, kernels #389) has closed and no CVE touches the pinned stack; **CANDIDATE** when one closed, which schedules an experimental-lane run in a daytime idle window (never a nightly lane swap on this hardware); **FORCED** only on a CVE or driver end-of-life. Promotion needs three green gate runs of the same image digest on three distinct days plus one release-tier run, never in a week tagged busy, at most one stable promotion per ~6 weeks, and always by a human `/promote` that only retags (`:stable-prev` is kept). The frozen stable lane is the product; the experimental lane is a question you ask when a specific tracked issue says the answer changed.

## 6. Judges' disagreements and rescued ideas

- **S39 (never-sleep + nightly reboot).** The value skeptic rated it low because 90 % of the idea is a 15-minute config change. The MVP and Reliability judges rank that 15 minutes first overall (8.5 each) because it removes the P6 trigger and is the only documented L0-leak reset; the Delight judge scored 4.0 since it fights the handheld nice-to-have. Resolution: ship the core; the battery choreography stays out.
- **S33 (Spark gateway).** Skeptic: low, because the leader-election/Syncthing-lock mechanism is a flapping machine. The cost, offline-while-travelling unless toggled manually, is accepted.
- **S05 (preflight).** Skeptic: medium ("consolidation of known rules"). MVP and Reliability rate it 8.0/7.0 because the `ExecCondition` no-restart-loop detail prevents the one failure that forces reboots; Delight 2.5. Resolution: build it inside the Quadlet, not as its own project.
- **S52 (pruned twin).** Skeptic: medium. MVP (5.0) and Reliability (4.5) lowered it because a crash-prone experimental process cannot sit beside the 18–20 GiB models without walking the leak ladder; the fix is "run it in the idle window with production unloaded, calibrate an A/A noise floor first".
- **S40 (probes and canary).** All agree on the core; the Reliability judge struck the chaos drill outright (kill -9, rtcwake and wlo1 drops are the three faults this hardware cannot self-heal), where the skeptic had merely tamed it.
- **S38 (watchdog).** Agreement on the ladder, but the Reliability judge adds that iTCO almost certainly does not exist on Lunar Lake and the iwlmvm reload in the existing resume unit is probably a silent no-op on iwlmld kernels; the fix is smaller and more urgent than the framing.
- **S01 vs S04.** The skeptic treats the facade and llama-swap as peers (both medium); the MVP judge ranks S04 well above S01 and would not build S01's 500–800-line SSE proxy until llama-swap is in place and a measured gap appears.
- **Delight-judge rescues.** S24 (paddle push-to-talk, 8.0), S27 (appliance face, 7.5), S26 (MCP body, 7.5), S21 (NPU dial tone, 6.5), S29 (quiet decode, 6.5) and S28 (fingerprint, 5.5) all carry skeptic "low" verdicts. ## 7. Rejected ideas

| id | title | why |
|---|---|---|
| S19 | Proxy-level quality insurance: cache_salt retry and n=2 tool-call race | Feasibility: feasible_with_changes (1–2 weeks, not a weekend). Value: **none**. The #53912 MTP+APC corruption exists only on the GDN hybrid, which is an *est.* row never measured on this console, and vLLM ≥ 0.28.1 disables Mamba/GDN prefix reuse with drafters anyway (#52047; #51250 reports ~0 % hits), so there is nothing for a salted retry to make harmless. | S20 | mmap expert paging for a second MoE | Feasibility: **infeasible**. Value: **none**. With `-ngl 99`, llama.cpp's Vulkan and SYCL backends copy every tensor into driver-allocated device buffers (shmem-backed xe GEM BOs; a Claw 8 log shows "SYCL0 model buffer size = 17596.43 MiB") and unmap the file, so the resident set is the whole model regardless of mmap. Top-8-of-128 load-balanced routing touches essentially every expert within ~100–200 tokens, so there is no 4–6 GiB hot set; with vLLM resident, ~290 cold expert slices (~750 MB) would be faulted per token (1.2–2.5 tok/s, below the idea's own floor) and every 5–8K-token Telegram prefill would stream the full ~16 GiB expert set once per ubatch (~50 s TTFT). It runs the box in the page-cache-pressure regime the owner already fled, conflicts with the drop_caches leak recovery, and halves the coder's decode. The problem it targets is solved for free by pointing the Telegram persona at the running vLLM endpoint. |

## 8. Experiments to run first

Each is cheap, decides several ideas at once, and has a measurable pass criterion. Run them on the stable lane in an idle window; none requires a Spark except where noted.

1. **What is the Shmem, really (S09, S11, S43)** — 30 min. Load the model, exit via SIGTERM and via SIGKILL (two separate cycles), and after each record `/proc/meminfo` Shmem/MemAvailable, `du -s /dev/shm`, D-state processes, `fdinfo` drm-resident totals, then `rm` `/dev/shm` orphans and `echo 2 > drop_caches`. **Pass:** XPU free (driver `getMemoryInfo`) returns to ≥ 26 GiB in 10/10 cycles without a reboot, which means the "leak" is reclaimable residue and the `ExecStopPost` sweep (not a reboot timer) is the fix; **fail** confirms a genuine L0 leak and keeps the nightly reboot as the backstop.
2. **getMemoryInfo vs MemAvailable (S10, S05)** — 10 min inside the frozen container. Print `torch.ops._C_cache_ops.getMemoryInfo(0)` and MemAvailable before/after `drop_caches` and after `cat shard > /dev/null`. **Pass:** free tracks MemAvailable within ±0.3 GiB and is unchanged by page cache → delete the UMA patch, lower `--gpu-memory-utilization` by ~0.08, close/reframe #40295/#41370.
3. **Does a hardware watchdog exist (S38, S39)** — 30 min. `ls /sys/firmware/acpi/tables/WDAT; modprobe wdat_wdt; ls /dev/watchdog*`, then 10 suspend/resume cycles with `RuntimeWatchdogSec=120` armed. **Pass:** `/dev/watchdog0` exists and 10/10 cycles produce no false reset; otherwise record "no hardware watchdog" and rely on never-sleep-on-AC plus softdog.
4. **Gemma 4 prefix caching on XPU (S17, S02, S51)** — 20 min. Send the same 8K-token chat request twice with `stream_options.include_usage`; read `usage.prompt_tokens_details.cached_tokens` and `vllm:prefix_cache_hits_total`. **Pass:** `cached_tokens ≥ 90 %` of `prompt_tokens` on the second request and TTFT < 1 s; **fail** means APC on the home-made FLASH_ATTN path is broken and every prefix-dependent idea is Qwen3-Coder-only.
5. **vLLM sleep level 2 on XPU (S07, T16, S39 battery branch)** — 2 h, `VLLM_SERVER_DEV_MODE=1 --enable-sleep-mode`. **Pass:** after `POST /sleep?level=2` MemAvailable rises by ≥ 15 GiB with GPUReclaim not growing, `wake_up` + `collective_rpc reload_weights` completes in < 30 s, and greedy parity vs a fresh start holds on 10 prompts (MTP off, since the drafter is not reloaded). **Fail** closes S07 and makes T16's game-watch a plain stop/start.
6. **The one-day bake-off (S08, S04)** — already planned. Gemma 4 vs Qwen3-Coder under pi on the five harness-study tasks, including streamed tool-call correctness (bug #41967) and a Qwen3-Coder-as-assistant run. **Pass:** Gemma 4 completes ≥ 4/5 tasks with parsed tool calls and no text-fallback failures → one resident model, llama-swap swaps only on explicit Qwen Code sessions.
7. **Hardware-truth sprint (S24, S25, S28, T14, T15, S21–S23)** — one day, in this order with kill criteria: `pw-record --rate 16000 --channels 2 test.wav` from the DMIC array (pass: non-silent audio in both Desktop and Gaming Mode); `lsusb` + `fprintd-list` (pass: a libfprint-listed USB ID); intel-npu-driver from COPR + `openvino_genai.WhisperPipeline('NPU')` on a 10 s clip inside an Ubuntu container with `/dev/accel/accel0` (pass: transcript within 2× realtime and a recorded tuple of kernel/firmware/UMD/OpenVINO versions); `dd` read test of an A2 microSD (pass: ≥ 150 MB/s). Every device-facing idea is gated on one of these; a fail retires the dependent ideas for this quarter.
8. **Clock-cap sweep (S29, T18)** — half a day. GT `max_freq` at rp0/1.6/1.4/1.2/1.0/0.8 GHz × two prompt shapes (1024/1024 and 8192/256), 3 runs each, recording tok/s, package W from `intel-rapl` and tokens/J; first verify a PL1 write sticks for 60 s and across one suspend. **Pass:** a point exists with ≥ 25 % lower package power and ≤ 10 % decode loss → ship a "quiet night" profile; otherwise drop profiles and keep only the J/token numbers for the transit rule.

## 9. Open questions

- **Is the L0 shared-memory "leak" real?** Finding 3 was measured on the v0.19 stack by hand; no one has characterized the residue (tmpfs vs TTM pool vs driver) on v0.32 + compute-runtime 26.27 under systemd `KillMode=control-group`. Experiment 1 decides whether the nightly reboot is a backstop or a crutch, and whether an upstream reproducer can be filed against compute-runtime.
- **Does S0ix preserve the Level Zero context?** Unknown; it decides whether battery suspend is ever a usable idle state or whether the handheld case must be a planned stop.
- **Does `/dev/watchdog` exist on this firmware (WDAT), and does Lunar Lake's iTCO ever get an i2c-i801 entry upstream?** Decides how much of S38 is hardware.
- **Which op-mode does the running kernel bind for the BE201 (iwlmld vs iwlmvm)?** If iwlmld, the existing `wifi-resume.service` has been a no-op and the D3cold workaround is doing all the work.
- **Does the DMIC array capture under Nobara, and does libfprint know the sensor?** Two 5-minute checks that gate roughly a quarter of the catalogue.
- **How is the Linux partition sized, and is snapper configured at all?** INSTALL.md says only "shrink Windows by ≥ 150 GB"; the answer decides whether T09/T08 matter and whether T11's subvolume snapshots need the swapfile moved first.
- **Can the Sparks suspend and wake on LAN?** No official NVIDIA statement; decides whether any Spark "herding" idea is possible or whether the Sparks simply stay on.
- **What does OpenClaw actually put in the system prompt per turn, and does its Telegram adapter expose a Bot-API base URL (`apiRoot`) or forward-origin in the prompt?** docs.openclaw.ai was unreachable in this run; these decide S02's measured hit rate, T03's Telegram leg and T07's taint trigger.
- **Does the work laptop have TB4/USB4 with admin rights, and does corporate policy allow mosh/Tailscale/agent forwarding on it?** Decides S31's TB-net leg and S34.
- **Will the gateway move to a Spark (S33 reversal) or stay on the Claw?** This single decision retires most of the on-console reliability ideas for J2 and changes where secrets, memory backups and the dead-man live. The nanobot-vs-OpenClaw bake-off should be settled first, since every OpenClaw-specific hook (approvals client, SecretRefs, sandbox config) may be thrown away.
- **Why does XPU weight ingest run at ~0.6 GiB/s from a warm page cache?** The one load-time question with real upside (P4), and an upstream vLLM-XPU item rather than a local patch.
