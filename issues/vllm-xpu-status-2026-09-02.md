# vLLM on Intel Arc 140V (Lunar Lake) — Status Report, 2026-09-02/03

Legend: **[confirmed]** = verified against primary sources by the skeptic pass; **[refuted→corrected]** = original claim was wrong, corrected text shown; **[unverified]** = not checkable from here. "User" numbers are your own measurements; everything else marked *est.* is an estimate.

## 1. TL;DR

- **Stack to install:** vLLM **v0.29.0rc1** (tag 33898f8, Sep 2) + **vllm_xpu_kernels 0.1.14.1** + **torch 2.13.0+xpu** + triton 3.7.2+xpu shim + auto_round_lib 0.14.2 + numba 0.65.0, Python 3.12, compute-runtime ≥ 26.18 (26.27 is upstream's Docker reference, 26.31.39395.13 is newest). v0.28.0 (stable, pins kernels 0.1.13.2) lacks the XPU Mamba/GDN prefix-caching crash fix (#48109) and the GDN-MTP kernel fixes (#537/#544). **[confirmed]** ([v0.29.0rc1 xpu.txt](https://raw.githubusercontent.com/vllm-project/vllm/v0.29.0rc1/requirements/xpu.txt), [#48109](https://github.com/vllm-project/vllm/pull/48109), [#54203](https://github.com/vllm-project/vllm/pull/54203))
- **Environment rules stand:** never source setvars.sh at runtime (upstream Dockerfile.xpu has no oneAPI at all since #45973); `SYCL_UR_USE_LEVEL_ZERO_V2=0` remains required by default because the V2 adapter is the default on Xe2/Lunar Lake in the DPC++ runtime. Correction to your notes: torch 2.13.0+xpu bundles the **oneAPI 2026.0** runtime (intel-sycl-rt 2026.0.0, libsycl.so.9), not 2025.3/.so.8 — that was torch 2.11. **[confirmed]**
- **Hardware is fine at the kernel-dispatch level:** `intel_gpu_lnl_m` is on the Xe2 allowlist (`is_xe2_arch()`, PR #240, since kernels v0.1.5); every Xe2 kernel family dispatches on it. Wheels are AOT-built for pvc/bmg only; on LNL the driver either uses the `64.bmg` fatbinary member via the BMG_G21→LNL_B0 compatibility mapping (compute-runtime ≥ 25.44.36015.5) or recompiles from embedded SPIR-V (older drivers) — which path fires on your box is **[unverified]** (watch for `-Wrecompiled-from-ir`). Nothing fails because of AOT targets.
- **MTP verdict:** Qwen3.5/3.6 (GDN) native MTP on XPU **works only with kernels ≥ 0.1.14 (i.e. v0.29.0rc1)**; on 0.1.13.x it crashes when spec and non-spec tokens share a batch and silently corrupts long-context output (#544). Run with `--no-enable-prefix-caching` (platform-agnostic #53912, unfixed). **[refuted→corrected]** Nemotron 3.5 native MTP: not verified working on XPU (0% acceptance was checkpoint-missing-MTP-weights + torch.topk NaN bug, fix only in torch 2.14) — DFlash is the proven speculator (1.8× on B70). Gemma 4 MTP: `torch.cuda.CUDAGraph` hard-coded in `gemma4.py` (only when draft uses ordered embeddings) — untested on XPU. N-gram: **broken on GDN models** (#54740 assert), fine on dense-attention models.
- **Model recommendation:** primary **Qwen3.6-35B-A3B GPTQ-Int4 (symmetric, MTP-weights-preserved checkpoint) + native MTP k=2–4**, expected ~2× over your 18–20 tok/s single-stream (*est.* from ~95% B70 acceptance); safe fallback **Qwen3-Coder-30B-A3B** (current driver) with prefix caching on + DFlash (`z-lab/Qwen3-Coder-30B-A3B-DFlash`, untested on XPU) or `ngram`.
- **Laguna XS 2.1 is blocked as published:** poolside's INT4 mixes INT4 + grouped-INT8 experts; the XPU MoE backend is INT4-sym only → auto backend raises `NotImplementedError`. Try `--moe-backend triton` first (TritonWNA16Experts declares XPU support, kInt8Static; untested), else requant to pure sym-INT4 gs32/128. Also: PyPI kernel wheels lack the causal+sliding-window head-128 prefill tuple → its 30 SWA layers would hit the PyTorch reference attention path unless you build kernels with `chunk_prefill_full.conf`. **[refuted→corrected]**
- **AWQ-packed MoE checkpoints do not work on XPU** (no AWQ→GPTQ repack; fix PR #48552 open; issues #54349/#54350). Use GPTQ-packed or compressed-tensors **symmetric** INT4 for MoE. **[confirmed]**
- **Your PRs:** #40295 and #41370 both open, needs-rebase since Jun 30. Since v0.25.0 (#47134) vLLM no longer calls `torch.xpu.mem_get_info` on XPU; it uses `torch.ops._C_cache_ops.getMemoryInfo` (Level Zero usable-mem extension, driver ≥ 26.18 does /proc/meminfo-based accounting for iGPUs). Re-measure before rebasing; the PR is now a ~37-line xpu.py-only change on top of the generic `is_integrated_gpu()` hook (#35356, in v0.28.0). **[confirmed]**
- **Keep XPU graphs off** (`VLLM_XPU_ENABLE_XPU_GRAPH` unset): grouped-GEMM tile-counter race fixes #457/#524 unmerged, GDN spec metadata under graph padding #389 open, V2-runner + structured outputs crash #53993 (fix #53997 open). Eager + V2 runner + async scheduling is the tested path.

## 6. Runtime SOTA on XPU (main / v0.29.0rc1)

- **XPU graph:** implemented (torch.xpu graph via `CUDAGraphWrapper`, #34482 Feb 25) but **opt-in** `VLLM_XPU_ENABLE_XPU_GRAPH=1` (#38193), single-GPU only, requires torch ≥ 2.11; default mode when enabled is FULL_AND_PIECEWISE (FA backend = UNIFORM_BATCH). Enable-by-default PR [#51600](https://github.com/vllm-project/vllm/pull/51600) is a draft needing torch 2.14 (Level Zero graph). Reported 4–6× decode on B70 (#50038, open), zero iGPU validation. Blockers: #457/#524, #389, #53993, #54785. **[confirmed]**
- **torch.compile:** on by default; XPU force-disables 6 fusion passes (gemm_comms, allreduce_rms, attn_quant, act_padding, rope_kvcache, rope_kvcache_cat_mla); static Triton launcher disabled under UVA offload. **[confirmed]**
- **Model Runner V2:** default on XPU (`XPUModelRunnerV2`), auto-fallback to V1 for ngram; escape hatch `VLLM_USE_V2_MODEL_RUNNER=0`. **[confirmed]**
- **Async scheduling:** default on, PP overlap #51650 (v0.28.0). **[confirmed]**
- **Prefix caching / chunked prefill:** default on, no XPU gating; XPU-specific landmines are hybrid-only: #48059 crash fixed by #48109 (v0.28.1rc0+); #53912 MTP+APC corruption open; #51250 says APC largely ineffective on GDN hybrids; #52047 (≥0.28.1) silently disables Mamba prefix reuse with drafters. GDN block_size rounded to multiple of 64; FA block ≥ 64. **[confirmed]**
- **FP8 KV:** supported (see §5). **HND layout** (#47975, `VLLM_KV_CACHE_LAYOUT=HND`): PD-disaggregation only, parity with NHD — ignore. **[confirmed]**
- **Attention backends:** default `FLASH_ATTN` (sycl-tla), auto-fallback `TRITON_ATTN` for fp32 / bidirectional MM masks; `TRITON_MLA` for MLA; `XPU_MLA_SPARSE` for DeepSeek DSA; TD loads on by default in Triton attn. `--attention-backend TRITON_ATTN` is the supported workaround if the preset gap bites. **[confirmed]**
- **UVA weight offloading** (#51770, v0.28.0): zero-copy host USM `--cpu-offload-gb`; no capacity gain on UMA except sidestepping the 28.57 GiB visible cap; costs the slow Triton launcher path. **[confirmed]**
- **DCP / FlashKDA / block-sparse attention:** no XPU code or validation (not found); only DSA via XPU_MLA_SPARSE. **[confirmed]**
- **New knobs:** `VLLM_XPU_FORCE_N_CONTIG_WEIGHT=1` (#53536, rc1, up to 2× bf16 prefill on B70, off by default), `VLLM_XPU_INC_WNA16_BACKEND`, `VLLM_XPU_USE_SAMPLER_KERNEL=1` (default), `VLLM_XPU_SPEC_DECODE_MAX_QLEN` (kernels, default 16). #52389 (rc1) fixes single-GPU oneCCL warm-up abort — directly relevant to a world_size==1 iGPU. **[confirmed]**
- Intel LLM-Scaler-vLLM 0.26.0-b1 (Sep 2) is rebased on vLLM v0.26.0, B60/B70 only — not an iGPU path. intel/ai-containers archived May 27. **[confirmed]**

([EnvironmentVariables.md](https://github.com/intel/llvm/blob/sycl/sycl/doc/EnvironmentVariables.md)) **[confirmed]**

## 9. Recommended install recipe

```bash
# driver: compute-runtime >= 26.18 (ideally >= 26.27); check
clinfo | grep -i "driver version"    # or rpm -q intel-compute-runtime
uv venv --python 3.12 ~/vllm-xpu && source ~/vllm-xpu/bin/activate
# v0.29.0rc1 wheel (commit 33898f832c53c3e98999e0ec2c689f61ee92a9bc); /nightly/xpu for main
uv pip install "vllm==0.29.0rc1+xpu" \
  --extra-index-url https://wheels.vllm.ai/33898f832c53c3e98999e0ec2c689f61ee92a9bc/xpu \
  --extra-index-url https://wheels.vllm.ai/xpu/ \
  --extra-index-url https://download.pytorch.org/whl/xpu \
  --index-strategy unsafe-best-match
# expect: torch 2.13.0+xpu, triton-xpu 3.7.2, vllm_xpu_kernels 0.1.14.1, auto_round_lib 0.14.2, numba 0.65.0
pip list | grep -Ei "^(torch|triton|vllm|auto.round|numba|intel-sycl-rt) "
# re-apply local patch: is_integrated_gpu() from PR #40295 onto vllm/platforms/xpu.py (file unchanged since Aug 13, should apply cleanly)
```

Runtime env (do **not** source setvars.sh; keep /opt/intel/oneapi out of LD_LIBRARY_PATH):

```bash
export SYCL_UR_USE_LEVEL_ZERO_V2=0          # still needed by default on LNL; re-test with V2 later
unset VLLM_XPU_ENABLE_XPU_GRAPH             # keep graphs off (#457/#524/#389/#53993/#54785)
export VLLM_XPU_INC_WNA16_BACKEND=w4a16     # only matters for AutoRound/INC checkpoints (#53211)
# optional experiment: VLLM_XPU_FORCE_N_CONTIG_WEIGHT=1 (bf16 layers prefill)

vllm serve <GPTQ-Int4-sym Qwen3.6-35B-A3B checkpoint with mtp.safetensors> \
  --dtype bfloat16 --max-model-len 65536 --max-num-seqs 4 \
  --gpu-memory-utilization 0.85 \
  --kv-cache-dtype fp8 \
  --speculative-config '{"method":"mtp","num_speculative_tokens":2}' \
  --no-enable-prefix-caching \
  --enable-auto-tool-choice --tool-call-parser hermes --reasoning-parser qwen3
```

Notes: leave ~1k tokens of headroom below `--max-model-len` (partial final MTP group); if the checkpoint's `quantization_config.dynamic` lacks a `-:…mtp…` exclusion the BF16 draft will fail to load — pick one that has it or apply the cookbook `patch_mtp_nightly`. For Qwen3-Coder-30B-A3B drop `--speculative-config`/`--no-enable-prefix-caching` (or use `{"method":"ngram",…}`) and keep prefix caching on.

Verify in the startup log: (1) `Using FLASH_ATTN backend` and **no** "XPU kernel not compiled for this config, falling back to PyTorch reference attention"; (2) `cudagraph_mode` forced to NONE message (eager) and `Using Model Runner V2`; (3) speculative config accepted (`num_speculative_tokens=2`, method mtp) and async scheduling enabled; (4) memory line from `getMemoryInfo` — free/total should look like MemAvailable-based (~28 GiB total); (5) `ldd $(python -c "import vllm_xpu_kernels,os;print(os.path.dirname(vllm_xpu_kernels.__file__))")/_xpu_C.abi3.so | grep sycl` → site-packages `libsycl.so.9`; (6) no `-Wrecompiled-from-ir` warning / no multi-GiB IGC spike (else driver < 25.44 → upgrade or build kernels with `lnl-m` AOT); (7) first request: greedy parity vs `--speculative-config` off, and a 16k-context generation without loops (#544 class).

## 10. What changed vs. the late-Aug notes

- **Version corrections:** native XPU INT4 MoE (#41426) shipped in **v0.23.0** (not v0.25); gs32 MoE (#45136) **v0.24.0**; Xe2/Xe3 gate in XPUExperts from v0.26.0 (#48079); native XPU GDN path is **#33657 (v0.20.0)** — #43565 (v0.23.0) only added MTP; NemotronH latent-MoE since v0.13.0.

- **Grouped-GEMM race fix "landed":** refuted — #457 and #524 still open; `at::empty` counter in 0.1.14.1.

- **XPU wheels/images:** now real (`wheels.vllm.ai/<commit>/xpu`, manylinux_2_34; `vllm/vllm-openai-xpu:v0.28.0` and nightlies).
